# ai-work-board

**Claude Code と共用する、手元の掲示板・連絡帳。**

```bash
npx ai-work-board
```

`http://127.0.0.1:3457` が開きます。

**Claude からのスレッドが、1件ずつ受付に出ます。** 読んで、その場で回答すると、次の1件へ進みます。

| | |
|---|---|
| **受付** | いまあなたを待っているスレッド。1件ずつ大きく出る |
| **Claude の番** | あなたが答えて、いま向こうが動いているもの |
| **片付いた** | 完了・取り下げ。押し間違えてもここから受付に戻せる |
| **タスク** | 未着手 / 着手中 / 完了 の3列。Claude も人も同じファイルを動かす |
| **セッション** | いま走っている Claude Code（書き忘れても自動で載る） |

スレッドには4つの種類があります — **判断**（決めてほしい）／**確認**（これでいいか）／
**作業依頼**（人にしかできない操作）／**共有**（報告）。

## 画面の見方

一度に見せるものは**紙1枚だけ**です。残りは要るときまで畳んであります。

**左に立っているのが「係」です。** いま何件たまっているか・急ぎがあるかを、姿勢とひとことで
言います。新しいスレッドが届くと、画面の外から歩いてきて紙を差し出します（急ぎのときは急ぎ足、
まとめて届いたときは束を抱えて）。押すと、いま言っているスレッドまで連れていきます。
裏のタブで作業している間に届いたぶんは預かっていて、画面に戻ったときに運びます。

**右の縦の棚が一覧です。** ふだんは絵と件数だけ。マウスを乗せる（または Tab で入る）と
名前が出ます。**色は2つしか使いません** —
テラコッタは「あなたの手が要る」（至急・回答するボタン・ターミナルで入力待ち）、
青鈍は「相手の番・動いている」。それ以外は白黒です。

キーボードだけで一周できます。

| キー | |
|---|---|
| `j` / `k` | 次の紙 / 前の紙 |
| `1`〜`9` | 選択肢を選んでそのまま回答 |
| `r` | コメント欄へ |
| `⌘Enter` | 回答して次へ |
| `t` `c` `n` `a` `i` | タスク / Claude の番 / セッション / 片付いた / スレッドを立てる |
| `u` | 直前の回答を取り消して受付に戻す |
| `?` | 使い方 |

明るさは OS の設定に合わせます。棚の一番下で「OSに合わせる → 明るい → 暗い」と手で
切り替えることもできます。

仕組みと語彙は、社内で実運用している「デスク」というシステムをそのまま踏襲しています。
200件以上を捌いてきた形なので、ここで作り直す理由がありませんでした。

まず画面だけ見たいときは、自分のファイルを一切読まないモードがあります。

```bash
npx ai-work-board --demo
```

## なぜ作ったか

Claude Code を3本も4本も並行で走らせるようになると、こうなります。

- Claude が聞きたいことは、**そのセッションのチャットの中にしかない**。別の作業をしていると流れる
- こちらが伝えたいことは、**そのセッションを開かないと渡せない**
- セッションが終わると、やりとりは会話ログに沈む。**次のセッションは何も覚えていない**

計器盤を作っても、これは解けません。見えるようになるだけで、やりとりは相変わらず
チャットの中だからです。必要なのは**両方が書ける場所**でした。

回答しただけでは完了になりません。Claude が動いた結果を見てから完了にする形です。
だから「答えたのに直っていなかった」を取りこぼしません。

タスクも同じ板の中にあります。スレッドとタスクが別の場所にあると、結局どちらも見なくなるので。

## 画面に出ているものは、全部ディスクから辿れます

カードの足元に、そのエントリのファイル名が出ています。押すと**フルパスと、その md の中身が
そのまま**開きます。画面がどこかで加工した要約ではなく、ディスクに在るとおりのテキストです。

「いまの作業」に自動で載るセッションは板のファイルではないので、代わりに**何を根拠に出しているか**が
開きます。状態は `claude agents --json`、直近の指示は `~/.claude/projects/…/<sessionId>.jsonl`
の末尾 256KB、というところまで、パスごとコピーできます。

読めないエントリがあったときも、「読めません」で終わりません。その場でファイルを開けるので、
どこが壊れているかを自分で見て直せます。

自分の手元で動いて、自分のファイルを読むツールです。**中で何をしているか見えないなら、
localhost で動く意味がありません。**

## 板の正本は md ファイル

画面は窓にすぎません。板の実体は、ワークスペースの中のただの md です。

```
<workspace>/.board/
├── items/*.md                    # スレッド（あなた ⇄ Claude）
├── closed/*.md                   # 片付いたもの
└── tasks/{inbox,doing,done}/*.md # タスク
```

```markdown
---
id: 20260921-104829-billing-rounding
title: 請求の丸めは切り捨てと四捨五入のどちらにしますか
kind: decision
priority: normal
status: open
project: billing
options: ["切り捨て（今のまま）", "四捨五入（会計に合わせる）"]
---

明細ごとに丸めるか合計で丸めるかで、月末の合計が最大3円ずれます。

## あなたにお願いしたいこと

1. どちらに寄せるかを決める
2. 決まり次第こちらで直し、テストを足して報告します
```

`status` が「いま誰の番か」を持ちます — `open`（あなた待ち）→ `answered`（Claude 待ち）
→ `closed`（完了）。回答は本文のあとに会話として積まれるので、**1件の中で往復できます**。

サーバが落ちても板は残ります。エディタで直接書き換えても壊れません。
Claude もあなたも同じファイルを読み書きします — それが「共用」ということです。

## Claude に板を使ってもらう — 初回に自動でやります

**板は、Claude が書いてくれて初めて板になります。** 取扱説明を読ませていないセッションは
板の存在すら知らないので、画面は永遠に空のままです（素の Claude Code で実測して、
そこが一番の分かれ目だと分かりました）。

なので、はじめての場所で立ち上げたときは**こちらで用意します**。

```
  はじめての場所なので、Claude が板を使えるようにしました:
  CLAUDE.board.md を作りました
  CLAUDE.md に @CLAUDE.board.md を1行足しました
```

- 足すのは **`CLAUDE.md` の1行だけ**。もとの中身は1文字も変えません
- **すでにあるものは上書きしません。** `CLAUDE.board.md` を手で直していればそのまま残します
- 2回目以降は何もしません（起動のたびに行が増えることはありません）
- いらないときは `--no-setup`。あとから消すのも、足した1行を消すだけです

## プロジェクトごとに1つ立てます

板の正本はワークスペースの中にあるので、**プロジェクトごとに1つ**です。
`npx ai-work-board` を叩いたディレクトリがそのまま板の置き場になります。

**ポートは自分で探します。** 3457 から順に空いている番号を使うので、
2つ目・3つ目のプロジェクトでもそのまま立ち上がります（番号は起動時に出ます）。
どの板を見ているかは、ブラウザのタブに出ます（`keyaki-env-01 · ai-work-board`）。

プロジェクトをまたいで1画面にまとめる機能はありません。

## データは外に出ません

- サーバは **`127.0.0.1` にのみ bind** します。公開用のオプションはありません（作っていません）
- **外部へ通信するコードがありません。** 実行時の依存パッケージはゼロです
- **あなたの `~/.claude/settings.json` を書き換えません。** hooks も入れません
- ただし「セッション」の一覧を出すために `claude agents --json` を起動します。
  そのとき **Claude Code 自身が自分の設定ファイル（`~/.claude.json`）を触ることがあります**。
  板が書いているわけではありませんが、板を起動した結果として増えるものなので書いておきます
  （テストで、板自身がホームに作るのは `access.log` 1本だけだと確かめています）
- ローカルネットワークに何も出しません。他のマシンを探しにも行きません
- アカウント登録も、APIキーの入力もありません

`127.0.0.1` に bind しただけでは安全ではない、ということも分かっています。
同じマシンのブラウザで開いた**別のサイト**は localhost に fetch できてしまうからです。
この板は書き込みを受け付け、それを Claude が読むので、守りが無ければ広告タグ1つが
Claude への指示チャネルになります。なので3枚重ねています。

1. **Host ヘッダの検査** — 攻撃者のドメインを 127.0.0.1 に向ける手（DNS リバインディング）を弾きます。読み取りにも掛けます
2. **Origin / Referer の検査** — 別オリジンからの書き込みを弾きます
3. **CSRF トークン** — 画面を実際に開いた人だけが書けます

**画面からの操作で書き込む先は `.board/` の中だけ**に閉じています。
板の外に触るのは、次の3つだけです（どれも止められます）。

| 何を | いつ | 止め方 |
|---|---|---|
| `CLAUDE.board.md` を置く | はじめての場所の初回だけ | `--no-setup` |
| `CLAUDE.md` に1行足す | 同上（すでにあれば何もしない） | `--no-setup` |
| `~/.ai-work-board/access.log` に日付1行 | 起動のたび | `--no-log` |

その隣は `~/.claude/settings.json`
（hooks ＝ 任意コード実行）なので、1階層の脱出がそのまま致命傷になるからです。

**これらは主張ではなくテストです。** `npm test` が、外部通信のコードが無いこと・
`settings.json` を書くコードが無いこと・パスの脱出が全部落ちることを毎回確かめます。

### 板の中身は「データ」であって「命令」ではない

ネットワーク側を固めても、**ファイルを置ける者は板に書けます**。同期フォルダ、
clone したリポジトリ、別のセッション。だから同梱の `CLAUDE.board.md` は、
板の内容を指示として実行しないことを Claude に明示しています。

画面から書いた伝言には `origin: board-ui` が付きますが、**これは出どころの保証では
ありません**（板に書ける者はこの行も書けます）。あくまで手がかりであって、
承認の代わりにはならない、という前提で書いてあります。

## オプション

```
-w, --workspace <path>  板を置く場所（既定: 今いるディレクトリ）
-p, --port <number>     ポート（既定: 3457 から空いている番号を自動で探す）
    --demo              自分のファイルを一切読まず、サンプルで画面だけ見る
    --no-open           ブラウザを自動で開かない
    --no-setup          CLAUDE.board.md の設置と CLAUDE.md への1行追記をしない
    --no-log            「その日開いたか」の記録（日付のみ）を残さない
```

`--no-log` について: 既定では `~/.ai-work-board/access.log` に**日付だけ**を書きます。
「毎日開いているか」を自分で測るためのものです。時刻も URL も IP も残しません。
`--no-log` を付ければ何も書きません。

## 対応環境

- Node.js 20 以上
- **macOS で動作確認しています。** Linux と Windows は未検証・サポート外です
- 明暗は OS の設定に追随します（画面からも切り替えられます）
- 「いまの作業」の自動部分は `claude` コマンドを使います。無い場合はその部分だけ「不明」と出て、板の4欄はそのまま使えます

## 直したのに直らないとき（npx のキャッシュ）

`npx` は同じ指定なら取り直さず、前に落としたものをそのまま使います。
なので直したはずの不具合が残っているように見えることがあります。

起動時に出る番号が、いま動いているものです。

```
  ai-work-board 0.2.0  http://127.0.0.1:3457
```

GitHub 側と違っていたら、コミットを指定すると取り直します。

```bash
npx -y github:keyakilabs/ai-work-board#<コミット>
```
